# Accessibility

This page records what the plugin actually does for assistive technology, what has been verified,
and what remains unverified. It deliberately avoids claiming support for specific screen readers or
speech output that has not been tested.

## Assistive MathML output

The **Assistive MathML** setting (off by default) controls whether each rendered formula also
carries a machine-readable MathML copy:

- The visible formula (CHTML or SVG) stays on screen; MathJax marks the visual output
  `aria-hidden="true"` so assistive technology skips it.
- A visually hidden `<latest-mjx-assistive-mml>` element is appended inside the formula container,
  holding the MathML serialized from MathJax's internal tree (`mi`, `mo`, `mn`, fractions, tables
  and so on). The element is clipped to 1px and marked unselectable, so it never paints or takes
  part in text selection.
- The plugin ships no speech engine. MathJax's SRE (speech renderer) is **not** bundled, so no
  spoken text or `data-semantic-*` annotations are generated by the plugin; speech depends entirely
  on the screen reader's own MathML support. This avoids duplicate speech nodes by construction.
- Toggling the setting rebuilds the private engine and clears the render cache, so output never
  mixes the two states. A cache hit hands out a deep clone that retains exactly one assistive
  MathML tree — pinned by `tests/MathJaxEngine.test.ts` for both renderers, together with the
  visually-hidden clipping rules and the absence of assistive output when the setting is off.

Behavior is identical for the CHTML and SVG renderers. The PDF export path uses the private SVG
engine and inherits the setting, so the same hidden MathML nodes are embedded in the print
document; how (or whether) a PDF viewer exposes them is governed by the PDF's own tagging and is
outside the plugin's control.

Obsidian's built-in formulas — sections we deliberately leave to Obsidian under the `obsidian`
fallback mode, hover previews and canvas cards — keep Obsidian's original accessibility behavior
unchanged.

## Keyboard interaction

The plugin adds no keyboard-operable controls and no focusable elements. Rendered formulas are
static DOM inside the note; caret movement, selection and Obsidian's own navigation are unaffected.
There is no keyboard trap surface to review: nothing the plugin mounts can receive focus.

## Verified environments

| Check | Where it is verified |
| --- | --- |
| Assistive MathML present only when enabled; single tree per formula; survives cache cloning; hidden-clip rules present | Automated: `tests/MathJaxEngine.test.ts` (both renderers) |
| Visual output unaffected, no duplicated on-screen formula with the setting on | Desktop acceptance on Windows 11, Obsidian 1.13.7 (see `docs/smoke-testing.md`) |

## Known limitations

- No screen reader is bundled or invoked. Whether NVDA, JAWS, VoiceOver or Narrator read the
  formulas well depends on each reader's MathML support inside Obsidian's Electron/Chromium
  engine. We have not run a reader pass yet; treat specific-reader compatibility as unverified.
- Speech-style navigation (subterm exploration, cycle through summands) requires MathJax's
  SRE/explorer extensions, which are intentionally not bundled.
- Hover previews and canvas cards are not taken over (see `docs/compatibility.md`); formulas there
  keep Obsidian's own rendering and accessibility behavior.
- `isDesktopOnly` remains `true` in `manifest.json`; no mobile accessibility claims are made (see
  `docs/mobile-spike.md`).
